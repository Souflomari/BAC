## Choice — `sma_asymptotes`

`sma_asymptotes` was the pre-designated slice 3 target: it had already
survived the 4-criteria filter in `sma_limit_calc.json`'s
`authoring_notes.candidates_cut`, was flagged `borderline: false`, and
was held back from slice 2 only for pedagogical-centrality and
stem-design reasons, not for any doubt about the candidate's quality.
No fresh candidate-selection deliberation was needed. The decision is to
ship exactly the candidate that was prepared: `limite-infinie-sans-asymptote`
as M1, plus whatever additional misconceptions the literature and cadre
support for this skill.

### Why these four misconceptions

**M1 — `limite-infinie-sans-asymptote`**
The carried-forward candidate. Sierpinska 1987 names the obstacle
explicitly ('actual infinity = dissolution of structure'). The Moroccan
cadre de référence SM-A 2006 names "étude du comportement à l'aide de
lim f/x" as a separate objective from "calculer lim f" — a distinction
that only matters if the wrong model exists. Bac SMA 2022 provides the
paper citation. Passes all four criteria. This was the founding reason
for this slice.

**M2 — `comportement-symetrique-plus-moins-infini`**
The cadre explicitly requires studying +∞ and −∞ separately. The
literature (Sierpinska 1987: treatment of ±∞ as "same number with
opposite sign") supports this as a named wrong model, not a
procedural skip. The key diagnostic criterion is that the wrong model
is only exposed on stems with √(x²+g(x)) or |x| forms — for rational
functions, the model happens to produce the correct coefficient (same
a at both infinities). This close-to-the-line property is documented
in authoring_notes.close_to_the_line. The Bac SMA 2021 citation is
specific (√(x²+1) form). Passes all four criteria.

**M3 — `asymptote-jamais-traversee`**
The most pervasive asymptote misconception in the international
literature. Tall & Vinner (1981) built the concept-image framework
partly on this obstacle; Naidoo & Naidoo (2007) provide the most
direct documentation for secondary-level students. This is a
pre-existing image-concept that students carry into the formal
definition lesson and that a clean presentation of the limit-based
definition does not displace. Including it here is justified because
it directly affects how students verify and interpret asymptotes in
the branches-infinies unit — a student holding this model will
incorrectly reject oblique asymptotes when the curve crosses the
asymptote line in a visible interval. Passes all four criteria.

**M4 — `branche-parabolique-confondue`**
A terminology misconception specific to the Moroccan cadre's
vocabulary. The term "branche parabolique" is Moroccan-syllabus
specific; this misconception is unlikely to be named in general
francophone-mathematics literature, which is why the evidence chain
leans on Sierpinska 1987 (first-example overgeneralisation as
obstacle) + the SM-A cadre definition + Bac SMA 2022 jury report
signal. The wrong model (branche parabolique = f is a parabola) is
clearly a named wrong belief, not a procedural error. The distractor
(B: "f est un polynôme de degré 2") is unambiguously generated by the
wrong model. Passes all four criteria.

### Candidates cut

**`asymptote-oblique-pente-seule`** (student computes a but omits b):
fails criterion (a) — this is a procedural omission (forgetting a
step), not a wrong model about the mathematical objects. The student
knows b exists; they failed to compute it. A wrong answer from a
procedural skip is not a misconception. Cut cleanly.

No other candidates were evaluated to the point of cut — the literature
and cadre scope for this skill are tight enough that the four shipped
items exhaust the well-evidenced wrong-model space.

## SMB twin analysis — does the "no unprefixed twin" pattern from slice 2 hold?

**Slice 2 finding:** `sma_limit_ops` had no SMB twin because SM-B's
cadre does not treat operations-on-limits as a standalone skill. The
legacy `seed_data.sql` math section has `limit_calc` and `limit_def`
but stops there — SM-B's content is narrower and never created the
downstream skills in the limit-operations or asymptotes domain.

**Slice 3 finding:** The same "no SMB twin" pattern holds for
`sma_asymptotes`, but the underlying reason is subtly different.

For `sma_limit_ops`, the argument was that SM-B's cadre doesn't isolate
limit operations as a separate skill. For `sma_asymptotes`, the argument
is stronger: branches infinies and asymptote analysis is a skill that
*belongs to the Analysis unit*, and the SM-B Analysis unit is
structurally present but covers it at a lower depth. The SM-B cadre de
référence does include asymptotes as a topic — a student studying SM-B
does encounter asymptotes — but the treatment is integrated into the
broader "étude de fonctions" skill rather than separated into a
standalone asymptotes skill. The `seed_data.sql` SMB math section likely
does not have a separate `asymptotes` or `smb_asymptotes` row; the
asymptote content is folded into whatever generic "étude de fonction"
skill exists.

The `asymptotes` (unprefixed) skill row does not exist at all — not as
SMB legacy, not as a shared unprefixed skill. This is consistent with
slice 2's finding that the unprefixed legacy rows (`limit_calc`,
`limit_def`) were created for SM-B content that pre-dated the SMA
prefix convention, and that topics introduced *after* that convention
(like the standalone asymptotes and limit-ops skills) simply never got
a legacy unprefixed twin.

**Practical consequence:** same as slice 2 — single-bank, cleanest
possible topology. No architectural complication for the encoder.

**Open documentation gap:** as noted in `_slice_2_skill_choice.md`, the
`architecture.md §5.5` bank-topology section over-generalises the
dual-bank pattern. That documentation fix is deferred; it is not in
scope for any draft slice.
